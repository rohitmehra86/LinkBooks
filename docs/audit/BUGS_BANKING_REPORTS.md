# Banking, Reports, Accounting and Tax — bug audit

- **Scope:** `src/routes/_authenticated/banking/*`, `src/lib/banking/*`, `src/components/banking/*`, `src/routes/_authenticated/reports/*`, `src/lib/reports/*`, `src/components/reports/*`, `src/routes/_authenticated/accounting.tsx`, `src/lib/accounting/*`, `src/components/accounting/*`, `src/routes/_authenticated/tax.tsx`, `src/lib/tax/*`, plus the RPCs, triggers and RLS policies they depend on.
- **Branch:** `cto-master-programme` at `c4b0cc8`. Read-only audit.
- **Method:** I read the code and traced each flow end to end (UI → server function → `post_journal` / table writes → reports). I ran SELECT-only checks on Supabase project `ipxflpzfcqwtenodbxwc` to confirm live RLS policies and look for data drift.
- **Note:** During the audit another session had uncommitted edits in `src/lib/accounting/accounting.functions.ts` (journal list filters and a new `getJournalDetail`), `src/components/create-new/JournalPanels.tsx` (multi-line journal totals, control accounts hidden, idempotency key reset after each post) and the banking subnav. Line numbers below refer to the committed `HEAD` version. Findings already addressed by that work are left out.
- **Related:** aged receivables "as at" and 1000-row issues on the sales side are in `BUGS_SALES_AR.md` (AR-08, AR-09, AR-26). They are not repeated here.

Severity scale:
- **Critical:** wrong ledger or reports, money double-counted, or an accountant is blocked from a core month-end task with no workaround.
- **High:** an accountant gets wrong numbers or is blocked from a core task.
- **Medium:** incorrect or misleading result, or a missing control, that has a workaround.
- **Low:** polish.
